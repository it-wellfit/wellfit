## 3. 詳細實作步驟

### T-01: 建立 .gitignore 與 .env.example

**目的**：確保本機優先，不將敏感資料提交到版本控制。

**動作**：
1. 建立 .gitignore，排除：target/, *.exe, *.dll, *.pdb, .env, *.secret, *.key, *.token, data/, *.log
2. 建立 .env.example，包含所有環境變數範例（不包含真實密鑰）
3. 驗證：git status 不顯示應被忽略的檔案

**驗收標準**：
- git status 不顯示應被忽略的檔案
- .env.example 包含所有環境變數範例
- 本地可安全修改 .env 而不影響版本控制

### T-02: 建立 CI/CD 工作流 (.github/workflows/ci.yml)

**目的**：自動化建置、測試、部署流程。

**動作**：
1. 建立 .github/workflows/ci.yml
2. 設定觸發條件：推送到 main/develop，PR 到 main
3. 工作項目：
   - check：cargo check --workspace --all-targets
   - clippy：cargo clippy --workspace --all-targets -- -D warnings
   - test：cargo test --workspace
   - compliance：執行 erify-compliance.ps1
   - validate-templates：執行 alidate-templates.ps1

**驗收標準**：
- 推送到 main 或 develop 時自動執行
- 任何檢查失敗時阻止合併
- GitHub Actions 結果頁面可查看詳細日誌

### T-03: 配置驗證機制

**目的**：確保配置檔案結構正確，防止配置錯誤導致運行時失敗。

**動作**：
1. 定義配置欄位契約
2. 新增配置驗證函數
3. 啟動時自動驗證配置
4. 無效配置時顯示錯誤欄位

**驗收標準**：
- 無效配置啟動失敗並顯示錯誤欄位
- 有效配置正常載入
- 缺少必要欄位時給出明確錯誤訊息

### T-04: 錯誤代碼系統 (ERR-001~ERR-99)

**目的**：統一錯誤代碼，便於追蹤與診斷。

**動作**：
1. 建立 crates/wellfit_core/src/error_codes.rs
2. 定義所有錯誤代碼與對應訊息
3. 所有錯誤回應包含錯誤代碼
4. 日誌包含完整錯誤上下文

**錯誤代碼範例**：
- ERR-001：配置檔案不存在
- ERR-002：配置欄位缺失
- ERR-003：資料庫連線失敗
- ERR-004：權限不足
- ERR-005：資料驗證失敗
- ...
