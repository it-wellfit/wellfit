# E.Sun 沙盒驗收執行手冊（OQ-E3 到手後機械化執行）

**文件編號：** 09-sandbox-acceptance-runbook  
**版本：** 1.0（Draft）  
**日期：** 2026-11-04  
**前置文件：** `06-test-and-acceptance.md`（TC 案例）、`08-open-questions-and-decisions.md`（OQ-E3）、`05-security-and-audit.md`  
**狀態：** 執行手冊（runbook）；OQ-E3 憑證到手前**不得**執行任何真實端點呼叫

---

## 1. 目的

當 E.Sun 帳戶經理交付沙盒憑證（OQ-E3 解除）時，以本手冊機械化完成從「憑證到手」到「OQ-E3 結案」的全部步驟：前置檢查 → 連線 smoke → 案例執行 → 證據歸檔 → 狀態更新。本手冊不重複 TC 內容，案例定義以 `06-test-and-acceptance.md` 為準。

## 2. 前置條件清單（全部 ✔ 才可開始）

| # | 檢查項 | 驗證方式 | 狀態 |
|---|---|---|---|
| C-01 | 沙盒端點 URL 與環境識別（正式/測試）書面確認 | 帳戶經理書面回覆 | ⚠ 待取得 |
| C-02 | 2-Way SSL 客戶端憑證（含私鑰）已安裝且未過期 | `Get-ChildItem Cert:\CurrentUser\My` 檢查指紋 | ⚠ 待取得 |
| C-03 | eToken / FXML 簽章元件可於測試機載入 | 元件版本檢查（pin V2.8） | ⚠ 待取得 |
| C-04 | 測試受益人帳號清單（沙盒專用，非真實付款對象） | 帳戶經理提供 | ⚠ 待取得 |
| C-05 | 網路可達沙盒端點（443/tcp、TLS 1.2+） | `Test-NetConnection <host> -Port 443` | ⚠ 待取得 |
| C-06 | 系統時間同步（NTP，誤差 < 1s，避免簽章時間戳失敗） | `w32tm /query /status` | ⚠ 待取得 |
| C-07 | CLI 真實派送路徑啟用（QR-06 stub 移除）＋憑證釘選設定（QR-02） | 程式碼變更 + 測試 | ⚠ 待開發（憑證到手後依指紋設定） |
| C-08 | 執行授權：專案負責人書面核可本次沙盒測試 | 授權紀錄 | ⚠ 待核可 |
| C-09 | 日誌去識別規則確認（帳號遮蔽、僅留末四碼） | `05-security-and-audit.md` 規範 | ⚠ 待確認 |

**禁止事項**：不得使用正式環境憑證、不得對真實受益人付款、不得將沙盒憑證提交版控。

## 3. 執行順序（依 TC 分組）

| 階段 | 案例（引用 06） | 目標 | 中止條件 |
|---|---|---|---|
| S1 連線 smoke | 無 TC：單一 `amount=1` 最小交易 | 驗證 TLS/簽章/端點可通 | 連線或簽章失敗 → 中止，記錄錯誤碼 |
| S2 單筆付款 | TC-P01 | 端到端單筆成功 | 連續 2 次非預期碼 → 中止 |
| S3 批次付款 | TC-P02, TC-P03, TC-P04 | 批次與錯誤隔離 | 任一筆金額/帳號異常 → 立即中止 |
| S4 狀態查詢 | TC-S01, TC-S02, TC-S04 | 查詢路徑 | 查詢逾時 3 次 → 中止 |
| S5 對帳 | 匯入沙盒回覆 → `import_results` → 對帳 | 冪等與對帳閉環 | 帳本差異 > 0 → 中止並保留證據 |
| S6 邊界（選配） | TC-P05..P08, TC-S03, TC-S05, TC-ST*, TC-FX* | 視帳戶經理允許範圍 | — |

每階段結束後：證據歸檔（§4）→ 更新 `08-open-questions` 的 OQ-E3 狀態。

## 4. 證據要求（每案例）

| 證據 | 格式 | 存放 |
|---|---|---|
| 請求／回應（去識別後） | JSON 檔（端點、時間、`rsStatus.code`、txSeq 清單；帳號遮蔽） | `artifacts/bankpay-sandbox/<日期>/`（不進版控） |
| 執行命令與版本 | 文字（CLI 版本、元件版本、批次 ID） | 同上 |
| 媒體檔與 SHA-256 | 檔案 + 雜湊 | 同上 |
| 結果摘要 | 本手冊 §3 表格填寫（PASS/FAIL + 錯誤碼） | 本文件附錄或獨立報告 |

**判定語意**：`PASS ≠ 未測 ≠ FAIL`（未執行案例標記「未測」，不得以 PASS 或 FAIL 代之）。

## 5. 完成判準與簽核

- S2–S5 全部 PASS（或 FAIL 項已有雙方確認之替代處置）→ OQ-E3 可標記 **Resolved (sandbox)**。
- 簽核：執行者（Dev）× 見證者（QA）× 負責人（PMT）。
- 結案動作：更新 `08-open-questions-and-decisions.md` OQ-E3 列、更新 `06` 文件狀態、將結果摘要提交 CHANGELOG。

## 6. 失敗處置（回復）

| 失敗情境 | 處置 |
|---|---|
| 憑證/簽章失敗 | 保留原始錯誤，聯繫帳戶經理；程式碼維持 stub（不得繞過驗證） |
| 端點不可達 | 檢查網路政策；記錄 `Test-NetConnection` 輸出 |
| 回應格式與 V2.8 不符 | 建立差異清單（claims-vs-evidence 格式），暫停後續階段 |
| 中途需回退 | 停用真實派送設定、恢復 mock 測試；沙盒證據保留不刪除 |

任何失敗都不修改 `06` 的預期值來遷就結果；差異一律進入待決清單。

## 7. 檢討條件

沙盒環境行為與 V2.8 規格出現系統性差異；或 E.Sun 通知沙盒政策變更；或正式切換前再驗證要求（Stage 3）時。
