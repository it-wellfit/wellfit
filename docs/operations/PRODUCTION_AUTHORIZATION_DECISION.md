# 生產授權階段決策紀錄（P-08）

**文件編號：** PROD-AUTH-DECISION-001  
**版本：** 1.0  
**日期：** 2026-11-04  
**狀態：** 決策建議（待治理核可）  
**依據：** FLAPS-ARCH-OPT-003 §18（稽核）、`docs/SECURITY_REVIEW.md`、`plans/adr/ADR-0004..0008`、`docs/SYNTHETIC_CAPACITY_BASELINE.md`

## 1. 背景

Phase 1–3 工程交付已完成並通過全部工程閘門（clippy／fmt／357 測試／cargo audit 0 漏洞／cargo deny 四項全過）。決策問題：**是否授權將 Wellfit 部署至生產環境？** 本文件以證據為基礎，對三個候選決策反覆權衡後給出建議。

## 2. 深思（論證過程）

### 支持與反對的證據盤點

| 支持面上證據 | 反對面上證據 |
|---|---|
| 工程閘門全綠（可重現命令） | 影子模式證據為 0（從未對真實 FlapsErp 資料執行） |
| 對帳/切換/演練機制完整且測試覆蓋 | 雙軌對帳從未對真實資料運行（99.5% 門檻未實證達成） |
| 安全掃描（audit/deny）通過 | 手動安全審查（P-02 端對端）未執行；S-03~S-05 未結 |
| 切換回退結構化（狀態機 + rollback 測試） | OQ-F1/F2 未回覆（政策與契約空白） |
| 效能基線可重現 | E.Sun 沙盒未驗證（若付款入範圍，缺口為關鍵） |
| Demo 可離線完整展示 | 無 CI/CD 遠端執行證據、無監控、無 on-call、無具名業主 |

### 候選決策權衡

**決策 A：立即授權全面生產部署**
- 誘因：動能最大化、交付感強。
- 致命缺陷：專案自身品質閘門明文要求 M1 影子證據、安全審查與具名權責；即刻上線等於在證據鏈為空時宣稱營運能力 — 直接違反 claims-vs-evidence 憲章原則與 M2/M3 的退出條件設計。
- 裁決：**否決**。

**決策 B：一律拒絕，待所有外部輸入齊備**
- 誘因：零風險、紀律最嚴。
- 缺陷：過度阻擋。Demo 與內部影子試行（唯讀、可回退）風險極低且為取得證據的**必要步驟** — 沒有它們，M1 證據永遠不會產生，形成死結。
- 裁決：**否決**（改採 C）。

**決策 C：階段式條件授權（staged conditional authorization）**
- 每一階段有明確條件、證據要求、可回退路徑與核可人；授權隨證據逐階放大。
- 與 ADR-0004（影子優先）、ADR-0008（階段切換）及 M1-M3 閘門完全對齊；把「授權」本身也納入同樣的紀律。
- 裁決：**採用**。

## 3. 決策

**不授權立即生產部署；授權階段式條件推進：**

| 階段 | 範圍 | 資料 | 授權狀態 | 前置條件（全部滿足才進入） |
|---|---|---|---|---|
| **Stage 0：Demo** | 本機展示（CLI、測試證據、切換演練） | 合成資料 | **✔ 立即授權** | 無（已就緒） |
| **Stage 1：內部影子試行** | 內部機器、唯讀擷取原廠輸出、影子比對 | 真實資料（唯讀、不外傳） | **條件授權**（專案負責人口頭＋書面紀錄） | S1-1 影子擷取規格完成；S1-2 唯讀保證（含 100 MiB 上限沿用）；S1-3 產出物存放與去識別規則確認；S1-4 回退＝停用腳本即可 |
| **Stage 2：受控試點** | 有限範圍雙軌（如：單一管道或 Reports 唯讀流程） | 真實資料（雙軌、不切換寫入） | **需具名核可**（PMT＋流程業主） | S2-1 影子差異清單 ≥ 10 批次且匹配率 ≥ 99.5%（以 ADR-0007 判定）；S2-2 回退演練通過（ADR-0008 drill）；S2-3 手動安全審查完成（S-03 結案）；S2-4 試點範圍與退出條件書面化 |
| **Stage 3：生產切換** | 依 ADR-0008 四階段推進至退役 | 真實資料（寫入） | **需治理書面授權** | S3-1 M3 全閘門證據；S3-2 OQ-F1/F2 已回覆或差異已書面裁決；S3-3 付款入範圍時 E.Sun 沙盒驗收完成（`09-sandbox-acceptance-runbook`）；S3-4 CI/CD＋監控＋告警＋on-call 就緒；S3-5 備份/還原演練；S3-6 具名業主簽核（產品/安全/維運/資料） |

## 4. 核可矩陣

| 階段 | 必要核可人 |
|---|---|
| Stage 0 | 無（專案內即可） |
| Stage 1 | 專案負責人（PMT），書面紀錄留存 |
| Stage 2 | PMT ＋ 對應流程業主（例：財務流程 → 財務主管） |
| Stage 3 | 治理四業主：產品、安全、維運、資料（依 ISO 治理缺口 P-08 精神） |

## 5. 立即行動（依本決策）

1. Stage 0 即可執行：安排 Demo（不需額外授權）。
2. 啟動 Stage 1 前置：完成影子擷取規格（S1-1）— 這是解開死結的關鍵一步。
3. 外部輸入軌道：OQ-F1/F2（11/19）與 OQ-E3 依收件手冊處理，不阻塞 Stage 1。
4. 本決策送 PMT 核可後生效；核可前維持「不部署生產」現狀。

## 6. 風險與回復

| 風險 | 緩解 |
|---|---|
| Stage 1 影子資料處理不當 | 唯讀、本機、去識別、100 MiB 上限、產物不入版控 |
| 階段被跳躍推進 | 核可矩陣 + 本文件條件清單；每階段轉換需重簽 |
| 外部輸入延遲（逾期未回覆） | 影子軌道不阻塞；月報揭露；2026-12-31 提案重送 |
| 證據造假/誇大 | claims-vs-evidence：每項條件對應可重現命令或快照 |

## 7. 檢討條件

任一階段條件實測失敗；或 E.Sun 沙盒結果與 V2.8 出現系統性差異；或治理業主於核可時附加新條件；或 2026-12-31 提案屆期時。
