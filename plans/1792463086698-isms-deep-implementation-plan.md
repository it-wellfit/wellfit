## 0. 目標與成功定義

### 0.1 目標
將 ISO/IEC 27001:2022 ISMS 從「文件套件」轉化為「可運作、可稽核、可機械驗證、可持續改善」的組織級治理骨架，且：

1. **務實導入於所有工作流程** — 35 條流程（P-FIN/P-OPS/P-HR/P-IT/P-PHY/P-LOG/P-RET/P-ECS/P-SVC/P-MKT/P-SUP/P-GOV）皆有權限控制、簽核、稽核軌跡。
2. **智慧化控管** — 20+ 項機械驗證（V-01～V-20）、資料驅動值域、SHA-256 雜湊、跨向一致性自動檢查。
3. **專業實際幫助到所有業務** — 財務/物流/電商/零售/人力/資訊/實體/治理八大領域各有控制焦點與可量測指標。
4. **整體架構最佳化** — 單一控制庫（93 項）、單一 SoA、單一證據索引、IMS/知識庫權威分工、三層證據模型。
5. **所有細節完善** — 文件管制格式、值域資料化、追溯不變量、失敗模式對策、DoD、回滾機制。

## 2. 整體架構最佳化

### 2.1 三層證據模型（E1/E2/E3）

```
┌─────────────────────────────────────────────────────────────┐
│  E1 宣告層（SoA / 範圍聲明 / 風險登錄 / 處置計畫）          │
│  → 版本化；變更需變更摘要與核准                              │
├─────────────────────────────────────────────────────────────┤
│  E2 實作層（政策 / 程序 / 角色矩陣 / 流程 / 訓練教材）      │
│  → 文件管制格式；受控發佈                                 │
├─────────────────────────────────────────────────────────────┤
│  E3 證據層（系統紀錄 / 簽核 / 報表 / 測試結果 / 稽核軌跡）  │
│  → 唯讀保存 + SHA-256 雜湊 + 索引；不可回寫來源            │
└─────────────────────────────────────────────────────────────┘
```

**不變量**：
- E3 不可修改；更正以新增版本並保留原版。
- E2 每次修訂都必須對應 E3 新證據。
- E1 狀態欄位與 E3 證據須一致（SoA 標「部分實作」者，證據索引必有對應之部分證據）。

### 2.3 資料驅動值域架構

```
┌─────────────────────────────────────────────────────┐
│  vocab/*.csv（11 份，UTF-8 BOM）                     │
│  欄位：vocab_set, code, label_zh, label_en,        │

│  verify-compliance.ps1（ASCII only）                 │

├─────────────────────────────────────────────────────┤
│  新增值域 = 只改 vocab/*.csv，不改腳本               │
│  新增綁定 = 在任一列補上 applies_to                 │
└─────────────────────────────────────────────────────┘
```

### 2.4 深度級別（D1/D2/D3）取代規模排除

| 級別 | 定義 | 測試強度 | 適用流程 | 對應欄位 |
|---|---|---|---|---|
| **D1** | 深度驗證 | 年度測試規劃 + 客觀證據 | 財務核心、作業核心、電商、治理、資訊 | `depth_tier=D1`，須有 `test_plan_cycle=年度` |
| **D2** | 標準控制 | 標準作業程序 + 定期複審 | 人力、實體、物流、零售、客服、供應商 | `depth_tier=D2` |
| **D3** | 登記控管 | 僅登記與監控 | 行銷、低風險周邊 | `depth_tier=D3` |

**不排除原則**：所有核心與周邊系統皆納入 ISMS 範圍；不因系統規模而排除。深度級別只決定控制深度與測試強度，不決定適用性。

### 2.5 四維控制狀態（不跳級）

| 維度 | 欄位 | 值域 |
|---|---|---|
| 設計 | `design_status` | 未設計 / 規劃中 / 已設計 |
| 實施 | `implementation_state` | 未實作 / 部分實作 / 已實作 / 不適用 |
| 運作 | `operating_effectiveness` | 未測試 / 未評估 / 有效 / 無效 |
| 證據 | `evidence_sufficiency` | 無 / 部分 / 充分 |

**不跳級規則**：未經獨立測試者不得填「有效」；未經設計者不得填「已實作」。遷移規則見 `templates/README.md` §4。
