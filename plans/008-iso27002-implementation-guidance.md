## 1. Statement of Applicability (SoA) — 適用性聲明模板

SoA 是 ISO 27001:2022 認證審核的核心文件，必須列出所有 93 項 Annex A 控制項，並對每一項聲明：

- **適用/不適用**
- **實作狀態**（已實作/部分實作/未實作）
- **控制目標**
- **實作方式摘要**
- **排除理由**（若不適用）

### 1.1 SoA 欄位定義

| 欄位 | 說明 |
|------|------|
| Control ID | A.5.1 ~ A.8.34 |
| Control Name | 控制項名稱 |
| Applicable | Y/N |
| Implementation Status | Implemented / Partial / Not Implemented |
| Control Objective | 控制目標 |
| Implementation Description | 實作方式摘要 |
| Exclusion Justification | 排除理由（若不適用） |
| Evidence Reference | 證據文件編號 |

### 1.2 SoA 摘要（Wellfit 現狀）

| 主題 | 總數 | 已實作 | 部分實作 | 未實作 | 不適用 |
|------|------|--------|----------|--------|--------|

| A.6 人員 | 8 | 1 | 1 | 6 | 0 |

## 2. ISO/IEC 27002:2022 實作指引 — A.5 組織型控制措施（37 項）

每項控制項包含：控制目標、ISO 27002 實作指引、Wellfit 適用性、實作建議。

### A.5.1 資訊安全政策
- **控制目標**：提供管理方向與支持，確保資訊安全政策與組織策略一致。
- **ISO 27002 指引**：
  - 政策應包含：目的、範圍、原則、角色與責任、合規要求。
  - 應由高階管理層核准、文件化、溝通並定期審查。
  - 應涵蓋：存取控制、資料分類、事件管理、業務連續性、供應鏈安全。
- **Wellfit 適用性**：適用。需撰寫 Rust 代碼庫的存取控制政策。
- **實作建議**：
  - 建立 `policies/access-control-policy.md`
  - 包含：角色定義、權限分配原則、MFA 要求、SoD 規則、JIT 授權程序
  - 高階管理層簽核後版本控制（Git tag）

### A.5.2 資訊安全的角色與責任
- **控制目標**：明確定義資訊安全的角色與責任。
- **ISO 27002 指引**：
  - 定義 ISMS 負責人（CISO）、資安經理、IT 安全、應用開發等角色。
  - 角色職責應文件化並溝通。
  - 適用於全員（含承包商與第三方）。
- **Wellfit 適用性**：適用。RACI 矩陣已定義於 001 計畫第 4 節。
- **實作建議**：將 RACI 矩陣正式化為 `roles-and-responsibilities.md`。

### A.5.3 職責分離
- **控制目標**：防止衝突職責導致未授權或未偵測的活動。
- **ISO 27002 指引**：
  - 識別衝突角色組合（如：開發者 + 生產部署者）。
  - 實作 SoD 矩陣並自動化檢測。
  - 例外需正式核准並定期審查。
- **Wellfit 適用性**：✅ 已實作。`SodConstraint`、`evaluate()` SoD 檢查。
- **實作建議**：增加 OPA 策略引擎自動化 SoD 檢測。

### A.5.4 管理層的責任
- **控制目標**：管理層承擔 ISMS 責任。
- **ISO 27002 指引**：管理層應簽署 ISMS 政策、參與管理審查、確保資源配置。
- **Wellfit 適用性**：適用。需管理層正式核准。

### A.5.5 與權威的聯繫

## 6. ISO 27005 風險管理方法論

### 6.1 風險評估流程

1. **資產識別**：識別所有資訊資產（MTRIX 檔案、SQLite 資料庫、CLI 工具、原始碼）。
2. **威脅識別**：識別對資產的威脅（未授權存取、資料竄改、服務中斷）。
3. **脆弱性識別**：識別資產的脆弱性（權限配置錯誤、SQL 注入、輸入驗證不足）。
4. **風險分析**：評估威脅利用脆弱性的可能性與影響。
5. **風險評估**：根據風險準則確定風險等級。
6. **風險處置**：選擇處置選項（避免、降低、移轉、接受）。

### 6.2 風險矩陣

| 可能性 \ 影響 | 低 | 中 | 高 |
|---------------|-----|-----|-----|
| **高** | 中 | 高 | 高 |
| **中** | 低 | 中 | 高 |
| **低** | 低 | 低 | 中 |

### 6.3 風險處置選項

| 選項 | 說明 | 適用場景 |
|------|------|----------|
| 避免 | 移除風險來源 | 某功能不再需要 |
| 降低 | 實施控制措施 | 最常見，如 MFA、PAM |
| 移轉 | 轉移至第三方 | 雲端服務、保險 |
| 接受 | 正式接受殘餘風險 | 低風險、成本效益考量 |
