## 3. 最佳調整方案（基於整合結果）

### 3.1 調整原則

1. **最小變更原則**：每次變更限定目標範圍，不以大規模重構掩蓋單一缺陷
2. **證據優先**：所有公開數字、合規聲明及完成狀態必須可追溯至可信證據
3. **漸進式推進**：先完成高價值、低成本的工作，再推進高成本工作
4. **風險降低**：每次演進必須降低整體風險，或提出明確且經核准的風險取捨

## 4. 下一個最小且高價值的工作

**建議：P0 建立 ADR 模板與首份 ADR（ADR-0001）**

這是主控規範第 12 節的明確要求，且目前完全缺失。ADR 是所有設計決策的追溯基礎，沒有 ADR 就無法滿足「可追溯」要求。

**執行方式**：
1. 建立 `plans/adr/` 目錄
2. 建立 ADR 模板 `plans/adr/ADR-TEMPLATE.md`
3. 建立 ADR-0001：Wellfit MTRIX 代碼庫採用 Rust 原生實作
4. 建立 ADR-0002：ISO 27001:2022 權限管理導入策略
5. 建立 ADR-0003：CLI 權限指派持久化至 SQLite

**驗收標準**：
- ADR 文件符合主控規範第 12 節結構（背景、問題、候選方案、決策、理由、安全影響、替代方案、遷移、回復、驗證、後續檢討）
- 每個 ADR 有唯一編號、狀態、日期、決策者
