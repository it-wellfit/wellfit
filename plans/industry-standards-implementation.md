# 產業專屬標準導入計畫

## 1. 電商產業

### 1.1 PCI DSS v4.0 付款卡安全

**問題**：電商平台處理信用卡資料，必須符合 PCI DSS 要求。

**導入步驟**：
1. 確定 SAQ 類型（SAQ A, A-EP, B, B-IP, C, C-VT, D, P2PE）
2. 完成 SAQ 自評
3. 實施 PCI DSS 控制措施（12 項要求）
4. 通過 QSA 審核（若需要）
5. 年度重新認證

**工具**：PCI DSS 合規平台（Secureframe, Drata）
**驗證**：SAQ 完成率 100%、QSA 審核通過

### 1.2 GDPR / Taiwan PDPA 個人資料保護

**問題**：電商平台收集大量個人資料，必須符合隱私法規。

**導入步驟**：
1. 資料盤點與分類
2. 建立隱私政策與同意機制
3. 實作資料主體權利請求處理流程
4. 建立資料外洩應變程序
5. 定期隱私影響評估（PIA/DPIA）

**工具**：OneTrust, TrustArc, Cookiebot
**驗證**：隱私政策完整、同意機制運作、外洩通報流程測試

### 1.3 OWASP Top 10 Web 應用程式安全

**問題**：電商網站面臨 Web 攻擊威脅。

**導入步驟**：
1. Web 應用程式安全評估
2. 實施 OWASP 控制措施
3. 定期滲透測試
4. WAF 部署
5. 安全開發生命週期（SDL）整合

**工具**：OWASP ZAP, Burp Suite, ModSecurity WAF
**驗證**：OWASP Top 10 全部通過、滲透測試無高危漏洞

## 2. 百貨零售產業

### 2.1 ISO 28000:2022 供應鏈安全管理

**問題**：百貨零售供應鏈複雜，需管理供應商安全。

**導入步驟**：
1. 供應商分類與風險評估
2. 建立供應商安全要求
3. 實施供應商審查流程
4. 監控供應商合規
5. 定期供應商稽核

**工具**：供應鏈管理系統、供應商評估平台
**驗證**：供應商審查完成率 100%、無未審查供應商

### 2.2 客戶資料保護（CRM 安全）

**問題**：百貨收集大量客戶資料，需保護客戶隱私。

**導入步驟**：
1. 客戶資料盤點與分類
2. 建立資料保留政策
3. 實作同意管理機制
4. 定期資料清理
5. 客戶資料存取控制

**工具**：CRM 系統、OneTrust
**驗證**：資料保留政策執行、同意機制運作

### 2.3 POS 系統安全

**問題**：POS 系統是百貨的關鍵基礎設施。

**導入步驟**：
1. POS 系統安全評估
2. 實施終端安全控制
3. 建立交易監控機制
4. 員工權限管理
5. 定期安全更新

**工具**：POS 安全管理、終端保護
**驗證**：POS 系統安全評估通過、無未授權存取

## 3. 財會產業

### 3.1 財務內部控制（COSO / SOX 404）

**問題**：公開企業必須符合 SOX 404 內部控制要求。

**導入步驟**：
1. 建立內部控制框架（COSO）
2. 實施 ITGC 控制措施（存取控制、變更管理、營運控制）
3. 建立財務報告控制（ITAC）
4. 執行內部控制測試
5. 外部稽核師審核

**工具**：Workiva, BlackLine, ACL
**驗證**：內部控制測試通過、外部稽核無重大發現

### 3.2 會計準則合規（IFRS / IAS）

**問題**：企業必須依 IFRS 編製財務報表。

**導入步驟**：
1. 評估 IFRS 對企業的影響
2. 更新會計政策與程序
3. 調整財務報表格式
4. 建立 IFRS 合規檢查清單
5. 定期 IFRS 更新培訓

**工具**：SAP, Oracle, QuickBooks
**驗證**：IFRS 合規檢查清單 100% 通過

### 3.3 資料分析與稽核（ISAE 3402 / SOC 1）

**問題**：服務組織需要提供控制報告給客戶。

**導入步驟**：
1. 確定控制目標
2. 實施控制活動
3. 建立控制測試程序
4. 執行 Type I 審核
5. 執行 Type II 審核（至少 6 個月）

**工具**：ACL, IDEA, Workiva
**驗證**：Type I/II 報告取得

## 4. 製造業

### 4.1 企業-控制系統整合（ISA-95 / IEC 62264）

**問題**：製造業需要整合企業系統與控制系統。

**導入步驟**：
1. 評估現有系統架構
2. 定義整合需求
3. 實施資料交換介面
4. 建立即時監控
5. 定期整合測試

**工具**：MES (Siemens Opcenter), ERP (SAP S/4HANA)
**驗證**：系統整合測試通過、資料同步延遲 < 1s

### 4.2 品質管理系統（ISO 9001:2015）

**問題**：製造業需要品質管理系統認證。

**導入步驟**：
1. 建立 QMS 文件
2. 實施品質控制程序
3. 建立內部稽核程序
4. 管理審查
5. 取得 ISO 9001 認證

**工具**：QMS 軟體 (ETQ, MasterControl)
**驗證**：ISO 9001 認證取得

### 4.3 環境管理（ISO 14001:2015）

**問題**：製造業需管理環境影響。

**導入步驟**：
1. 環境影響評估
2. 建立環境管理程序
3. 實施環境監控
4. 法規合規檢查
5. 取得 ISO 14001 認證

**工具**：環境管理系統
**驗證**：ISO 14001 認證取得

## 7. 驗證與測試矩陣

### 7.1 產業 × 驗證方法

| 產業 | 驗證方法 | 頻率 | 負責角色 |
|------|----------|------|----------|
| 電商 | PCI DSS SAQ/QSA、OWASP 滲透測試、GDPR 合規檢查 | 年度 | 資安團隊 |
| 百貨 | 供應商審查、客戶資料保護檢查、POS 安全測試 | 季度 | 資安 + IT |
| 財會 | 內部控制測試、IFRS 合規檢查、SOC 1 審核 | 年度 | 財務 + 稽核 |
| 製造 | ISO 9001 稽核、ISA-95 整合測試、環境監測 | 年度 | 品質 + IT |

### 7.2 完成定義（Definition of Done）

只有在適用條件均獲得證據支持時，才能標記為完成：

- [ ] 需求與驗收條件明確
- [ ] 實作符合既定架構與不變量
- [ ] 安全及資料風險已評估
- [ ] 必要測試已實際執行
- [ ] 關鍵測試通過
- [ ] 未解決缺陷已揭露並依政策處理
- [ ] 靜態分析及建置結果有紀錄
- [ ] 變更與需求可追溯
- [ ] 文件與 ADR 已同步
- [ ] 監控及回復方案已確認
- [ ] 必要證據已保存
- [ ] 殘餘風險已揭露
- [ ] 完成狀態未超出實際驗證範圍
